# OVERFLOW · 溢彩

**▶ 在线试玩 <https://fanquanpp.github.io/overflow-pigment/>** · 约 20 分钟 · 中英双语 · 无构建步骤、零依赖

**一个颜料混合解谜游戏** · 六个画册 · 108 个棋盘

用 three.js 写的完整解谜游戏。棋盘统一是方格铺砌，剪影（环形、束腰、十字、菱面……）负责改变棋盘的形状；每一步把一种颜料扩散到某片同色连通区域里，把整盘收束到目标色。

关键在于**混合是真的**：

```
青 + 藤黄 = 绿          品红 + 藤黄 = 红          品红 + 青 = 紫
朱砂 + 花青 = 浑绿（真实的红加蓝就是这样，模型不替它掩饰）
```

这不是调色板查表，也不是 RGB 插值。颜料用**反射率曲线**建模，混合用 **Kubelka–Munk**——颜料层混合的标准近似。所以青加黄是干净的绿，而红加蓝是浑褐：红颜料吸收蓝、蓝颜料吸收红，两边都丢了。这是这套机制唯一不可替换的部分。

```bash
cd color
node tools/serve.mjs          # → http://127.0.0.1:8080/
```

必须通过 HTTP 打开。项目用 ES modules + import map，`file://` 下会被浏览器拦掉。

线上版本从 `https://fanquanpp.github.io/overflow-pigment/` 提供，是仓库根目录的静态文件，由 GitHub Pages 直接托管——没有构建步骤，所以部署就是推送。`npm run serve:prefix` 用 `/overflow-pigment/` 子路径在本地复现同样的目录结构，专门用来提前抓出"以裸 `/` 开头的路径"这类只在 Pages 上才暴露的错。

```bash
npm run assets       # 可选：下载 Inter 字体（118 KB）。不下载也能跑
npm run check        # 全部校验：网格几何、色彩模型、108 个关卡、管线冒烟
npm run levels       # 重新生成关卡内容（约 5 分钟）
npm run validate     # 只校验已提交的关卡
```

## 玩法

底部的调色坞里是这一册用到的颜料，每个都带编号、符号，以及**还需要它的格数**——不是棋盘上有多少，而是还差多少。这个数字就是这一盘剩下的工作量：它随解题下降，目标用不到的颜料恒为 0（于是变灰、不再是合法选择），瓶颈是哪个颜色一眼可见。

选一种颜料，点一个色块。**它周围同色的整片连通区域**一起变成"原色 + 这种颜料"的混合。一次操作，不管涉及多少格。

两种目标：

- **统一**：全盘收束到同一个混合色。目标色里有什么颜料，就只给你那些颜料，所以不存在死局，张力全在步数预算上。
- **配方**：棋盘上标出一些格子，各自要求含有指定颜料，其余格子自由。自由格不计分、挡在路上，而且是把两个标记格连成一片、让一次操作同时满足两者的唯一材料。

三种规则：

| | 移动效果 | 目标 | 为什么总是可解 |
|---|---|---|---|
| `mix` 混合 | 区域色 = 原色 ∪ 颜料 | 相等 | 所有格初始 ⊆ 目标，并集只会加 |
| `replace` 替换 | 区域色 = 该颜料 | 相等 | 覆写不累积，逐个区域刷成目标即可 |
| `recipe` 配方 | 区域色 = 原色 ∪ 颜料 | 包含 | 加颜料不会"越界"，不存在废掉的可能 |

核心策略是**先合并、再统一**：两片区域只有变成同一个颜色才能并起来，所以最省的解法总是先把区域并成大块、再一起收尾，而不是一格一格地补。

**练习室**：主页上的「练习」给一块随叫随到的 8×8 随机棋盘——用画册同一条生成管线、同一个分析器，难度取中档。它不记进度、不出结算卡，结束只给一条提示和"再来一块"的按钮。用来试一套颜料的脾气，或者放空脑子。

## 视觉

**俄国构成主义 + 瑞士国际主义。** 不是引用，是照着两边的做法做：

瑞士那一半给的是**系统**——严格的网格、齐左不齐右的正文、四层字号而不是十层、用发丝线做结构（而不是用框和阴影）、白底、没有圆角、没有渐变、没有透明、没有模糊。后面每一个都是"回避对网格做决定"的方式。

构成主义那一半给的是**声音**——纸白与墨黑之间的唯一一抹信号红、被当作构图元素而不是数据使用的巨大编号、有理由才出现的斜线、硬偏移投影（像一张印张压在另一张上）。

两边真正共用的部分才是有用的部分：有限的调色板、一个网格、以及"读者是聪明的"这个假设。

棋盘是唯一的例外，而且是刻意的：整个界面里只有它出现大量颜色，因为分辨颜色就是这个游戏本身。严格的单色框住唯一一片彩场——这既是瑞士的想法，也是呈现一个颜色谜题唯一诚实的做法。

**界面结构上只有一条内容栏。** 内容居中、限宽在一行舒适的尺度内（约 1020px），两侧留出的空白就是棋盘的位置——它作为背景存在，而不是占据一栏和文字抢注意力。三种"音量"：

| 状态 | 棋盘 | 用在哪 |
|---|---|---|
| `focus` | 占满屏幕，只给 HUD 两条规则线让位 | 游玩 |
| `hero` | 首屏下半幅，横贯整宽，标题卡浮在其上 | 主页第 1 页 |
| `ambient` | 退到背景，透明度 0.34 | 其余所有页面 |

**主页是分页的，不是一条长滚动。** 五个可切换的页——开始 / 混合 / 水波 / 印法 / 内容——每页正好一屏，不需要滚动。长竖直面板被否掉的原因很直接：它把论点、网格、印法和数据摊成一条没有层次的纸带，而且为了让棋盘始终可见，它不得不永久占据一栏。

**调色板用连续渐变表示，不用色块。** 色带的插值走 OKLab，也就是棋盘上颜色过渡走的同一个空间，所以它显示的是这个画册真实的色彩体积，而不是七个硬台阶；带上的刻度是棋盘真正能到达的那些混合。混合演示里的三条色带是"颜料 → 混合色 → 另一颜料"的三段渐变，中间那一段就是模型算出来的结果。

**六本画册共用一种印刷语言**（胶印 offset：涂布白卡、中性墨、边缘利落）——画册改变的是**颜料**（每一册一套自己的调色板），不改纸与墨。曾打算给每册配一种印法，实际上主题表里从未有过对应的键，六册全部落在同一个回退主题上；这一版把这个事实正式化：一套语言，省下的功夫花在水波与练习室上。

五个效果在这套语言里的对应：

- **折叠**——纸的折痕。瓦片绕自己的一条铰链线翻过去，露出纸背（不是更多墨）。每个瓦片的铰链方向是伪随机的，所以一片区域同时折起来像瓦顶，不像一张纸。
- **镭光**——那一抹信号红。悬停时整片区域（因为一次操作作用于一片区域）亮起红边，刚落子的瓦片闪一下红边。都是平涂，没有辉光：会发光的信号就不再是信号，只是特效。
- **反射**——印张自己的压痕。一块硬边、偏移、压暗的复制，贴在纸面上。之前那版画的是镜面倒影，那是另一套视觉语言里的东西。
- **水波**——一步操作不是一次铺满。变化从点击的那格开始，按 BFS 圈层逐圈延迟展开（每圈约 55ms），像墨落在湿纸上；撤销与重置则整片同时归位，因为那是修正，不是事件。
- **色彩过渡**——两个颜色在 OKLab 里走。sRGB 直插会让蓝→黄中途塌成灰，而这个游戏的全部难度就是分辨两种颜色，一个经过泥浆的过渡恰好在玩家核对目标的那一刻把目标变难读。

**色彩保真是一条正确性要求，不是偏好。** 渲染器用 `NoToneMapping`，灯光加起来约等于 1，所以哑光表面几乎原样复现它的反照率——混合模型算出的颜色就是屏幕上的颜色。同样因为这个，辉光被整个移除了：辉光会把一个亮色渗进邻居，而这个游戏问的就是"这两格是不是同一种颜色"。

## 怎么跑

需要 Node 18+，只用来起静态服务器。

```bash
node tools/serve.mjs                    # 默认 8080
node tools/serve.mjs --prefix=color      # 模拟 GitHub Pages 子路径
```

`--prefix` 存在的原因：项目站点从 `https://<user>.github.io/<repo>/` 提供，任何以裸 `/` 开头的路径都会 404。本地先跑一遍能提前抓到。

打开页面后：点底部编号色块选颜料 → 点棋盘上的格子 → 整片连通区域改变混合色。

键盘：`1`–`5` 选颜料，`Z` 撤销，`R` 重置，`H` 看一个解法，`Esc` 暂停。

## 核心机制

### 颜色状态是一个颜料集合

一格的颜色是**它含有哪些颜料**——一个位掩码——而操作是"加入颜料 P"。这让这个运算：

- **封闭**：并集还是集合，调色板永远不会跑出模型之外
- **可交换**：加颜料的顺序无所谓
- **可结合**：怎么分组无所谓
- **幂等**：加一种它已经有的颜料什么也不发生

前三条让玩家有可能推理一个混合；第四条让一次冗余操作可以被检测并拒绝，而不是悄悄吃掉一步。

因为封闭，一个三颜料画册正好七种颜色，而七种已经接近"整个难度就是分辨颜色"的谜题的上限了。四颜料给十五种混合，但它们要挤在同一个色彩体积里，于是开始出现落在恰可察觉差以内的成对颜色。这不是感觉——`tools/validate-color.mjs` 会量出每一套调色板的最小 OKLab 距离，只有标了 `ship` 的才用作关卡内容。目录里没有"暖色系"调色板，因为三个颜料挤在同一片色相区域时，根本产生不了七种能被分辨的颜色。

### 一次操作在屏幕上做什么

反馈是分层的，所以玩家不用读 HUD 就能知道发生了什么：

| 层 | 作用 |
|---|---|
| 折叠 | 变了的瓦片翻过去，铰链方向逐格伪随机 |
| 颜色 | 在 OKLab 里走到新的混合色，途中不掉彩度 |
| 信号 | 边缘闪一下信号红——平涂，靠网点印在纸上 |
| 声音 | 区域自己的音高 + 颜料自己的音高，**音程就是反馈** |

声音那一层值得单独说：一种颜料有音高，一个混合色有它各个颜料音高的平均，所以给一片已经含有该颜料的区域加同一种颜料是一个同度（听上去什么也没发生），而合并两片区域是一个五度或八度（听上去是个解决）。玩家在读到 HUD 之前就听出了好操作和废操作的区别。音阶是大调五声，所以任何顺序都不会难听。

### 悬停

悬停一格会点亮**整片区域**，因为一次操作作用于一片区域，玩家选的是区域不是格子。同时显示预览：当前色 + 选中颜料 → 结果色，以及"这一步会让几格越过目标"。

## 工程上值得说的几处

### 解析式拾取，不是 raycast

`InstancedMesh.raycast` 会遍历每一个实例并测它的几何体。三角瓦片又薄又尖，这么做既慢、在接缝处又不准。这里改为把指针射线和棋盘平面求交，再用 `grid.pickAt` 解析——近似格子 + 精确包含判定，也就是 `validate-grid.mjs` 校验过的那套数学，所以一次点击不可能落在不存在的瓦片上。

棋盘会在鼠标下倾斜，这时世界空间的 `y = 0` 平面已经不在瓦片所在的位置了，于是射线先被搬进棋盘的**局部空间**再求交。对任何倾角都是精确的。

### 取景是投影拟合，不是包围圆

把棋盘的**包围圆**塞进视场是最自然的做法，而且框得很差：棋盘是从上方五十度看的平面，近半被放大、远半被缩小，投影出来是个中心明显低于屏幕中心的梯形。包围圆看不见这件事，因为它从不投影任何东西。

所以这里真的去投影：放好相机，把棋盘的角点（以及印痕的角点、以及棋盘在最大倾角下的角点）投到屏幕空间，量出真实的包围盒，然后修正。修正必须分成两路——**距离**沿轨道移动相机（只改缩放），**视锥偏移**平移取景（只改位置）。把它们分开是全部诀窍：第一次写的时候我让相机和它的注视点一起移动来重新居中，那在投影上不是线性的，会过冲、会发散，拟合跑到离棋盘十六个单位的注视点上去了。

### 状态事件是自描述的

`play` 发出的 state 事件带着 HUD 需要的一切，而不是假设 HUD 已经先被告知了关卡。一个"必须先调用别的东西才能工作"的状态事件，就是一个带隐藏前置条件的状态事件——而它正是让每一盘的第一帧都崩掉的原因。

### 没有构建步骤

`vendor/three.mjs` 从游戏真正 import 的几个入口出发，跟着每一条相对 `from './x.js'` 把依赖闭包走完。addon 的依赖集没有任何地方记录，手工拷文件是确保 404 的可靠方式。bare specifier `three` 被刻意跳过——它由 import map 解析。

## 关卡是怎么来的

108 个棋盘不是手写的，也不是随机撒的。

**难度曲线是量出来的，不是写出来的。** 生成器先造一个候选池，参数横跨棋盘尺寸、剪影蒙版、规则集和碎片化程度；把每一个都用校验器用的同一个分析器测一遍；然后用最接近每个目标值的候选填满六个难度档。

反过来做——先定一章的参数，再指望它产出标签上写的难度——经不起和棋盘接触：同一个碎片化数量在满板矩形上很轻松，在环形剪影上很凶；而 `replace` 棋盘要达到同样的长度，需要的区域数比 `mix` 棋盘多一个数量级。先测量让标签为真，也让曲线上的空洞表现为一个填不满的档位，而不是一个悄悄比名字更容易的关卡。

**棋盘生成不是搜索，是构造。** 先按随机多源生长把棋盘切成有机的连通块（前沿从随机位置弹出，而不是按顺序——顺序 BFS 出来的是圆形领地，随机弹出出来的是手绘谜题那种犬牙交错），再给每块分配一个目标色的**部分**混合。安全性质因此自动成立：所有格初始都是目标的子集，并集只会加，所以每一格都能独立走到目标，不会越界。

**步数预算是安全的包线。** 束搜索是启发式的，它的结果对束宽**并不单调**——窄束可能碰巧在更浅的深度上找到解。所以预算取自最宽的一次实测加余量，并且校验器会重放一条解来确认它真的能在预算内完成。

**可证明的最优解是拿不到的。** 泛洪填色类谜题是 NP-hard 的，三色就已经是了。所以这里给的是：一条真实走过、可重放的解（因此预算一定可达），以及一个可采纳的下界。两者都印在解法面板上，宽窄一眼可见。

## 无障碍

- **色盲**：每个调色板颜色都带一个符号和一种纹理，忽略颜色也能读懂棋盘。符号按子集的**秩**索引而不是位掩码，所以秩是稠密的——四颜料画册的十五个条目拿到十五个不同的符号，而不是在位掩码的公共位上撞车。纹理在设置里可以叠到瓦片上。
- **图案本身就是这套视觉语言的原生元素**：网点、线屏、交叉排线——印刷业最先解决了这个问题。
- **对比**：每个瓦片有墨色关键线，而且关键线跟随瓦片真实轮廓，所以相邻瓦片永远不靠色差分开。
- **明度分层**：调色板的显示色被压进一个明度带并给了彩度下限，所以不会有一格黑得像背景、也不会有一格亮得消失。
- **减弱动效**：缩短转场、停止相机视差和棋盘倾斜、关掉纸纹。注意动效是缩短而不是移除——一个没有确认反馈的谜题是没法玩的。
- **画质**：辉光已经没有了，所以画质档位管的是像素比和印刷模拟的多少（网点、套印偏移、纸纹）。

## 已知限制

- **预算基于启发式实测**，不是最优解。一个足够聪明的玩家有可能找到比"标准步数"更短的路径，那样这一盘的标签就偏高了。关卡越长越可能出现。
- **束搜索随棋盘增长**。最大的棋盘（9×9，81 格）在宽束下要几百毫秒；这发生在生成期和提示按钮，不在渲染循环里。
- **纸面网格是屏幕空间外的世界空间图案**，所以在极端倾角下会看出它是贴在平面上的，而不是纸本身的纹理。
- 六个画册里有几个第六章棋盘没打满目标难度（候选池里够难的板子用完了）。校验器会把这些报出来，而不是掩饰。
